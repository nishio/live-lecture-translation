# 認識の区切りと更新用バッファを比較する

`lecture_asr_probe.py` は、16 kHz・モノラル・16 bit PCMの非圧縮WAVを入力とし、準備済みのローカル認識器を使って最大360秒の音声を異なる長さで認識する実験用コマンドです。次の実行は新しいモデル推論を開始します。クラウドAPI、マイク、実行中のアプリは使いません。出力先は `results/audio-experiments/` 内の新しいディレクトリに限り、既存結果を上書きしません。

```sh
.venv/bin/python audio-array/lecture_asr_probe.py /absolute/path/lecture.wav \
  --seconds 325 --chunk-seconds 3 5 10 15 30 --repeats 2 \
  --output results/audio-experiments/chunk-comparison
```

最初の最大15秒でモデルを準備し、その時間は別に記録します。各条件で末尾の短い区間まで認識し、2回目は条件の順を逆にします。認識器の設定は英語、temperature 0、前回テキストの引き継ぎなしで固定です。実験では2〜30秒を指定できますが、ライブアプリの既定値や選択範囲は変更しません。

更新間隔と認識する音声の長さを分ける例です。

```sh
.venv/bin/python audio-array/lecture_asr_probe.py /absolute/path/lecture.wav \
  --seconds 325 --chunk-seconds 3 --window-seconds 15 --repeats 2 \
  --output results/audio-experiments/rolling-comparison
```

この例は音声時刻3秒刻みの時点を想定し、その時点で利用できる直近最大15秒を認識し直します。冒頭は3、6、9秒と音声が増え、入力の末尾でも最後のフレームまで扱います。重なった結果は**更新可能な暫定スナップショット**です。そのまま連結したり、すべてを新しい発話として翻訳したりできません。確定部分の判定、重複の調整、翻訳前の再認識はライブアプリに未実装です。

`manifest.json` に条件、入力・モデルの同一性、完了・失敗・未実行の区間、準備時間と各呼び出し時間を保存します。音声と認識の生データも同じignoredディレクトリに残します。共有推論ロックを使用し、待ち時間を別に記録します。

結果中の公開時刻と平均待ち時間は、測定した処理時間を「音声が区切りまで届いたら1つの処理器で順番に認識する」モデルに当てはめた**推定**です。無音も含む音声時間で重み付けし、ローリング方式では新しく届いた音声だけを分母にします。モデル準備、外部の推論待ち、ライブの制御、ブラウザ描画は含みません。また、その区間のすべての単語が実際に認識されたことを表す値ではありません。

実行済みの比較と判断は[2026-10-05の実験記録](experiments/asr-chunk-duration.md)を参照してください。

実行前にリポジトリの [README](../README.md) に従って環境と認識モデルを準備してください。入力音声は別途必要です。
