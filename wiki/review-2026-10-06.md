# Whole-repository review after 1.0 (2026-10-06)

A read-only review of the 1.0.0 tree (commit `2be891f`) by four parallel reviewers (core runtime, cloud stages, UI/demo, repository/docs), with selected claims re-read in the source. It is a work queue, not a statement that every item is a defect: items marked *verified* were re-read in the code; others are reviewer reports with the stated uncertainty. The bundled-demo commit `9966092` landed after the review and does not touch the core findings; it does supersede the remark that the public sample was unused by any UI.

No capture, model inference or paid API request was performed. Test status at review: 576 CPU-only Python tests passed in `.venv` (2 opt-in native skips) and both Node UI suites passed. A system `python3` with a broken Homebrew numpy namespace produced six spurious numpy errors; run checks in the project environment.

## Reusable lessons

- **Check a finding against tests that encode policy before calling it a defect.** The reviewer read the cross-session block of identical failed input as a bug; an existing test showed it is the deliberate no-automatic-resend rule for possibly billed attempts. The real gap was diagnosability: the refusal carried the generic `unknown` category. Reviewer severity is a candidate, not a verdict.
- **"Unknown completion" must be earned.** Failures that happen before any inference is sent (connection refused, model listing, slot wait timeout) are not unconfirmed inference. Classifying them as unknown permanently halts recognition with no recovery path.
- **Durable write, then publish.** Translation already persists evidence before advancing coverage; recognition and analysis publication mutate state first. A failed append then leaves state and evidence disagreeing.
- **A budget stop is not a measurement.** Raising the charge to the whole daily budget to block further spending must not be recorded as `usage_confirmed` cost; keep measured cost and blocking charge separate.
- **A demo must not hide failures.** Hiding a whole details container to simplify the demo also hid analysis/ASR failures that the playback faithfully reproduced.
- **Skipped is not passed.** CI reported success while 17 tests (launcher, media decode, native capture) were skipped for missing zsh/ffmpeg/macOS.

## Findings

### High
1. *verified, then reclassified as deliberate* — Prior-session failure blocks identical input (`event_insights_cloud.py`, fingerprint lookup across all ledger entries); see Follow-up.
2. *verified* — Local mode without a running Ollama permanently pauses ASR via `inference_unconfirmed` (`lecture_live.py` `_analysis_failed`).
3. *verified* — Over-estimate actual cost recorded as the full daily budget with `usage_confirmed=True`.
4. *verified* — ASR lines published to state before `transcript.jsonl` append; same order in `_publish_analysis`.
5. `lecture_verify` ignores the translation stage (failed or pending lines still yield `verified_complete`).
6. Provisional WAVs are never deleted (~0.4 GB/hour estimated, unmeasured) and free space is checked only at start.
7. CI skips launcher, media-decode and native tests; CI uses Python 3.12 while the release check used 3.14.

### Medium
- Global app lock held across deep copy, ledger reads and fsync; GET snapshot mutates state.
- `CaptureSession.start` builds the Swift helper and spawns under `_lock`; Stop during start blocks the app.
- Readiness publishes `reachable: None` while probing; jobs treat it as offline.
- One timing drift or queue overflow ends capture for the rest of the lecture (deliberate; reconsider as an explicit gap).
- `_run_child` only sends SIGINT; the child may survive; the real implementation is untested.
- Failed requests keep their full conservative reservation with no reconciliation path.
- Budget/scope ledgers are per checkout (possible double budget with the originating project; unverified).
- `http.client.HTTPException`/SSL errors not classified as transport, so not retried.
- O(N²) set rebuilding in translation planning under the lock.
- Prices and model names duplicated in several modules; legacy `event_insights.analyze` path bypasses scope reservation.
- *verified* — Start notification reports success for `starting`/`stalled`; the migration patch no longer applies (`git apply --check` fails at `app.js`), and the stop side was partly resolved separately.
- Full-state polling every 2 s with no revision/diff and no hidden-tab backoff.
- Uncertain source text distinguished only by low-contrast gray and hover title; several helper texts below WCAG AA; no font-size control.
- Unrecognized intervals are invisible inside the source scroll and catch-up page.
- Auto-opening processing details shifts the reading area.
- Stale analysis has no freshness indicator near the headline.
- Transitive dependencies are unpinned; `.gitignore` lacks common video/audio/image extensions outside `data/`.
- The Codex-subscription evidence lives only on an experiment branch; `experiments.json` and migration follow-up statuses are stale.
- `start.command` hard-codes model and port; model metadata stores an absolute path.

### Low
- Token URL file written with default umask and token left in the address bar.
- Duplicate atomic-JSON writers, WAV inspectors and model metadata; very large `lecture_live.py`/`createApp`.
- Demo `formatTime` lacks hours; demo HTML assembled by unchecked `str.replace`.
- No `pyproject.toml`; unexplained `audio-array/` directory name; CHANGELOG heading and "release candidate" wording drift; README omits the Node requirement.

## Confirmed sound
Text rendering avoids `innerHTML`; HTTP binds to 127.0.0.1 with Host/Origin/cookie checks; parallel budget reservations are serialized; no key or error-body leakage found; uncertain lines stay translation targets; README languages agree and relative links resolve.

## Follow-up
High items 2–4 were fixed after the review, and item 1 was narrowed:

- **Item 1 is deliberate, not a defect.** `test_timeout_keeps_full_reservation_and_prevents_retry_after_restart` encodes that a failed or unknown attempt may already be billed, so identical input is never re-sent automatically, even after restart. The fix kept that rule and replaced the `unknown` category with `previous_attempt_failed` / `previous_attempt_unresolved`; manual retry is unchanged.
- **Item 2.** Refused connections, model selection/input-limit failures before dispatch, and slot-wait failures carry `local_inference_finished`. A slot-release failure after dispatch does not.
- **Item 3.** The ledger keeps the blocking charge and adds `measured_nanodollars` without a new state value, so older readers still fail closed. Confirmed cost and holds use `confirmed_nanodollars`.
- **Item 4.** Transcript and analysis history are written before publication. An ASR measurement-write failure is recorded as `asr.measurement_error` instead of marking the published chunk failed.

High items 5–7 were addressed next:

- **Item 5.** `lecture_verify` now requires a completed translation stage with no pending targets and no live worker when translation is enabled. It also checks that blocks cite existing, non-overlapping source lines and match `translation-history.jsonl`. In a snapshot, history may lead state, so a prefix match is enough. Cost-only histories without published translation are not reconciled.
- **Item 6, measured.** In the 325-second Audrey runs, preview WAVs took about 40 MB, against 20 MB for raw PCM plus chunk WAVs. Each preview WAV is now removed after its recognition returns or fails. The preview history keeps the frame range and PCM hash, so a window can be re-derived. Existing sessions are not cleaned up.
- **Item 7.** CI adds a macOS job on Python 3.12 and 3.14 with native tests enabled and the pinned decoder installed, plus a zsh syntax check. Any skipped test fails that job. Locally, all 592 tests ran without skips. A naive `grep skipped` would have matched test names containing "never_skipped", so the check matches only unittest's skip markers.

All other items remain open unless a later log entry says otherwise.
