# Provisional live recognition and translation evidence

Early recognition need not be append-only or serve as the final translation evidence. A short update interval can refresh a revisable buffer at the live edge; translation can re-recognize a longer span of already captured audio. Evaluate update interval, audio-window length, and finalization policy as separate parameters. A shorter input failing at a sentence boundary is a reason to test retained audio context and revision, rather than a reason by itself to delay every live update.

Keep provisional snapshots separate from the immutable source lines currently consumed by translation and analysis. At translation time, freeze the recognized audio range and source revision used by the request. Do not change the text behind an existing source ID, append overlapping snapshots as duplicate speech, or discard an unsuccessful revision. Preserve publication times so later corrections do not appear early in historical playback. The property “may still change” is distinct from the recognizer's uncertainty flag.

Both quick recognition and longer re-recognition use local inference capacity. Measure their contention as well as recognition time, missing words, revision frequency, and reader effort. Longer context does not automatically establish greater accuracy. A rolling-window probe can test available context and compute cost, but does not by itself implement stable-prefix reconciliation or the two-stage live pipeline.

The [authorized 325.567-second comparison](../docs/experiments/asr-chunk-duration.md) ran independent 3/5/10/15/30-second chunks twice and a 3-second refresh of a trailing 15-second window twice. Measured service medians were about 0.654 seconds for independent 3-second chunks, 0.771 seconds for 15-second chunks, and 0.777 seconds for the rolling snapshots. Simulated mean waits were about 2.15, 8.24, and 2.29 seconds respectively; these exclude startup and browser arrival. Selected rolling snapshots revised repetition and boundary failures when more audio became available, but also showed provisional regressions. This experiment selected the 3-second refresh and 15-second window; it did not itself integrate them into the live application or establish general accuracy.

## Implemented provisional display

The live CLI and recorded-audio runner enable revisable recent recognition in the main 「原文」 view by default. Every three seconds of confirmed stored audio makes a new trailing window of at most 15 seconds eligible for recognition. A single local worker prioritizes immutable source chunks and coalesces overdue previews to the newest available window. Three seconds is the requested refresh interval, not a guaranteed publication delay; model initialization, recognition and contention add time.

Each preview is a complete revisable snapshot with its own revision, audio range, uncertainty and actual publication time. It occupies one replaceable tail in the main 「原文」 scroll area. Canonical rows entirely before its window remain above it; overlapping or boundary-crossing rows remain intact under 「前の認識を見る」 until canonical recognition catches up. Segment timestamps do not supply a reliable word boundary, so the UI neither clips words nor claims semantic reconciliation. Preview IDs never enter the immutable transcript, translation coverage or analysis selection. The existing 15-second source chunks and frozen cloud requests retain their evidence contract. Stable-prefix reconciliation and longer translation-time re-recognition remain unimplemented.

Successful snapshots and failed attempts are saved separately in ignored session artifacts. Saved-result playback selects the latest snapshot that had actually been published at the playback cursor, including after backward seeks; older sessions retain their original timing and display. Never move old recognition results earlier to simulate faster inference. Explicit stop prevents new preview work under the same session cancellation rules as canonical recognition, while natural file completion still drains canonical work.

Use `--provisional-refresh-seconds 0` to disable previews; `--provisional-window-seconds` controls their context window. Changing `--chunk-seconds` still changes canonical recognition rather than the preview refresh interval. The [architecture](../docs/architecture.md) describes the current separation.

The user correctly observed that the separate preview pane and primary 15-second circle still made 「原文」 feel unchanged. The main original-text flow now prioritizes the latest preview, and its circle follows the three-second preview schedule while enabled, showing busy through initialization and recognition. Disabled previews and older runs retain the canonical schedule. The UI follow-up reuses the already recorded 84 Audrey previews at their actual publication times; it adds no inference, API requests or earlier timestamps. The preceding experiment remains a record of its original implementation.

## Translation boundaries before provisional-ASR integration

Source inspection showed that the continuous translator used `flush=True` for every request. Its capacity-only planner did not detect sentence completion: even `flush=False` would release unfinished text at a group limit or an excluded source row. Holding only the newest segment would also miss sentences split by internal request groups. ASR stability, sentence completeness, recognition uncertainty and request cadence are separate properties.

The first implementation keeps existing immutable source rows and adds a pure boundary planner before the shared translation adapter. Each capped group backs up to a sentence-like row end where possible; otherwise the tail waits. Common abbreviations, initials, ellipses and dangling connectives are excluded from this punctuation heuristic. The live lookahead threshold is two seconds of successfully processed audio after a candidate row end. It does not establish stability through repeated recognition, and with 15-second ASR chunks the observation delay is not necessarily two seconds.

The timeout threshold is 30 seconds of processed-ASR progress after the oldest unresolved row ends, not elapsed wall time or incoming capture duration. Limits, source barriers, known failed recognition spans, this timeout and end-of-input drain can release explicit fragments. The frozen selection and persisted blocks record why each boundary was chosen; fragments must not be represented as proof of a complete sentence. Failed recognition remains failed even when all eligible earlier text has been translated. Oversized rows remain pending with an explicit failure.

No-ready planning is a normal continuation wait. It neither calls the model nor advances the generation cadence, and the UI uses a static 「文の続き待ち」 indication. The last recognizer must finish before final drain; retry jobs remain frozen and history must be saved before coverage advances. Once history and coverage are saved, a later measurement or cost-report failure must remain visible without retaining the saved translation as a retry target. These lifecycle rules are covered with synthetic fixtures and providers, independently of recognition or Japanese quality.

Whole-row coverage deliberately holds a row such as a complete sentence followed by an unfinished clause in full. Translating only its completed prefix requires immutable source revisions plus character spans or derived unit IDs. The next ASR stage should connect the provisional buffer and longer re-recognition to that evidence contract, without changing text behind existing IDs. The two- and thirty-second thresholds need matched evaluation using actual publication events; no new model or live-comprehension improvement is established by the implementation.

## Uncertainty and translation eligibility are separate decisions

After publishing the comparison, the user proposed filtering rule-identifiable junk from uncertain recognition and translating the remaining content with its uncertainty attached. The reason is semantic preservation: excessive uncertainty detection followed by blanket exclusion can remove a negation, condition, quantity, or qualification. The subsequent implementation uses the conservative versioned policy described below; adopting it in a running session still requires a separate runtime transition.

Before this change, the [translation planner](../audio-array/lecture_translation.py) excluded every uncertain line from translation targets, but could send those lines as nearby context. Its normalized source retained `uncertain` but dropped `doubt_reasons`. The analysis selector excluded uncertain lines before building the request. Merely adding uncertain context did not require its meaning to appear in a target translation.

The 15-second experiment had 15 uncertain lines containing 161 normalized tokens. Five lines, containing 79 tokens, were marked uncertain solely because model timestamps extended outside their audio chunk. This is not evidence that their text is wrong. Text review also found excluded negation-bearing lines. Counts describe this one recording and the current heuristics, not validated error rates.

Separate three properties: the original recognition evidence, typed uncertainty, and the derived decision to include or suppress it in a translation request. Preserve source IDs, original text and every exclusion reason. A translation request should be able to include an uncertain target with an allowlisted reason; unsupported scores must not be presented as calibrated probabilities. Timing uncertainty and textual uncertainty should not be conflated. Translation output must retain unresolved wording or gaps rather than turning guesses into confident facts.

| Candidate treatment | Constraint |
| --- | --- |
| Suppress or collapse evident generated loops | Compression ratio is a suspicion signal, not proof of duplicate speech. Define and validate the repetition rule; preserve the original records and distinguish genuine emphasis or repeated speech. |
| Omit isolated nonsemantic fillers when the rule is reliable | Do not globally remove `so`, `thank you`, short responses, numbers, or negation. Context can make them meaningful. |
| Include meaningful uncertain text with its reason | Protect negation, quantities, conditions, names, attribution, and incomplete but informative clauses. Re-recognition may help resolve them. |
| Split or explicitly defer oversized text | Length alone is not a reason to discard content. Retain pending work and report input-limit failures. |

### Implemented source policy, version 1

The shared [source policy](../audio-array/lecture_source_policy.py) now keeps meaningful uncertain text in translation targets and analysis selection. It excludes only empty text, uncertain English rows made entirely of `um`/`uh`/`erm`, and a narrow duplicate artifact. A duplicate must be adjacent, have exactly the same text, language and times within one ASR chunk, have invalid-timestamp reasons on both rows, and have a repetition reason on the later row. Keep the first copy and record the later source ID's `duplicate_of`. Real repetitions across time, repetition scores alone, long text, `so`, negation, numbers and thanks remain available. An oversized retained row fails explicitly and stays pending.

Original source records remain unchanged. Derived exclusion audits are separate from coverage. Both translation planners, analysis selection, pending counts and final drain use the shared rules. Excluded text is also removed from translation context, avoiding accidental reintroduction. Requests carry canonical `uncertain` and allowlisted `doubt_reasons`; unknown or missing uncertain reasons normalize to `unknown`. Reasons enter source fingerprints and frozen retries. Timing-only uncertainty is distinguished in prompts from unreliable wording; unresolved content must not become a confident claim. Saved blocks preserve uncertain source IDs and their reasons.

New request selections and session state carry policy version 1; runtime manifests also record it and include the policy source file. Unmarked old histories and saved views retain their historical eligibility rules. Synthetic tests cover meaningful uncertain input, narrow exclusions, hashing, retry/failure/final drain and replay compatibility. That implementation verification did not measure generated Japanese quality; the subsequent real-data comparison is recorded below. Live-comprehension improvement remains unmeasured. The provisional display described above does not change this policy; longer translation-time re-recognition remains separate work.

Applying version 1 to the saved 15-second ASR experiment, without new inference, retains 12 of 15 uncertain lines (131 normalized tokens) and excludes three identical invalid-timing duplicate rows (30 tokens). Both recorded repetitions give the same selection. All five timestamp-only uncertain rows (79 tokens) remain included. This measures selection, not correct recovery of meaning: no listening-based false-exclusion rate or new Japanese translation was evaluated. Private inputs and derived per-source decisions remain ignored; only aggregate counts are recorded here.

## Decisions from the actual translation comparison

The [Audrey comparison](../docs/experiments/uncertain-translation-audrey.md) supports three reusable decisions:

1. **Uncertainty is evidence to carry, not a blanket instruction to discard.** Losing an uncertain prefix can change the polarity of a later, otherwise usable clause. Keep meaningful uncertain text in the translation target with its reason; nearby context alone does not guarantee that its meaning reaches the Japanese output. Timing-only uncertainty does not establish that the words are wrong.
2. **Evaluate meaning as well as coverage.** Hold ASR, model and available context fixed when comparing selection policies. Check negation, quantity, conditions, attribution and unresolved fragments against the supplied source before calling a larger target count an improvement. This trial observed one inverted and one omitted negation in the old output; the candidate preserved both. It did not establish the correctness of the underlying speech recognition or a general accuracy score.
3. **Treat remaining noise as a separate follow-up.** Two suspicious repetitive rows survived with an uncertainty notice. That notice did not remove the reading burden. The reading UI already groups case/whitespace variants for display, but that does not remove model-input targets or duplicate Japanese output; inspect source IDs and actual request/output coverage separately. Consider case/whitespace normalization only within the existing same-chunk, matching invalid-timing duplicate constraints, and test real emphasis, distinct time spans and meaningful short/long statements before broadening suppression. Do not revert to blanket uncertainty exclusion or remove `so` merely because it is short.

The normalization change above is a candidate, not implemented or revalidated by this file-back. Translation-time re-recognition is also separate work. Preserve the original rows, exclusion reasons and frozen request provenance for either approach. The trial's candidate implementation was in the working tree; recording or committing its measurements does not publish that code or change a running session. The aggregate report retains the USD 0.097502 confirmed trial cost and the one-lecture/one-output-per-condition limits; new source text, Japanese output and request/response evidence remain ignored.
