# live-lecture-translation

[English](README.md) | [日本語](README.ja.md)

Macで英語の講義を聴きながら、文字起こし、日本語訳、要点、概念の説明を読めるアプリケーションです。マイクでの録音にも、録音済みの音声にも対応しています。

**このプロジェクトの目的は、外国語の講義をリアルタイムで理解する力をAIで増強することです。** 英語を母語としない人にとって、英語の講義についていくには、母語で聴くときよりも追加の認知的リソースが必要です。AIがその言語的な負担を引き受け、講師が伝えようとしている内容の理解に、より多くの注意を向けられるようにしたいと考えています。

講義を聴きながら、「今何が話されているか」「ここまでどういう話をしてきたか」「何が重要な概念か」を短時間でつかみ、少ない負担で話についていけることを目指しています。

## 主な機能

- 選択したMacの音声入力を録音し、MLX Whisperで文字起こしします。
- 原文を上、日本語訳を下に表示します。翻訳は蓄積され、次の更新でも消えません。
- 話題、話の流れ、要点、重要な概念を整理し、「いま伝えていること」と「言葉の補足」を表示します。
- 表示を固定して読み続けたり、以前の要点に戻ったり、概念の説明を履歴から読み返したりできます。
- 録音・音声認識・翻訳・理解支援の処理状況を個別に確認できます。クラウド処理が遅延・失敗しても、それを理由に録音を止めない設計です。

文字起こしデータはローカルに保存されます。Codexなどのコーディングエージェントがその保存先を参照できる状態なら、エージェントのチャットで「ここまでの議論を整理して」「この概念を講師はどう説明していた？」といった質問もできます。質問するときは、参照する文字起こしのファイルや保存先を指定してください。

結果の表示には、音声認識・通信・生成の待ち時間がかかります。翻訳は通常60秒、要点・概念説明は通常120秒間隔が目安ですが、毎回その間隔で更新されるとは限りません。操作の詳細は[操作ガイド](docs/operation.md)を参照してください。

画面は日本語で、英語の講義を聴きながら日本語で理解を補う使い方を想定しています。音声認識では言語の自動判定と日本語も選べます。日本語の原文は日本語への翻訳対象にはなりません。

**1.0.0-rc.1**はApple Silicon Mac向けのリリース候補です。講演で使う前に[リリースノートと検証状況](docs/release-1.0.md)を確認してください。v0.9.0からの変更は[変更履歴](CHANGELOG.md)にまとめています。

## 必要なものとセットアップ

文字起こしにはApple Silicon搭載MacとPython 3.12以降を使います。マイク録音用の小さなプログラムをMac上でビルドするため、AppleのCommand Line Toolsに含まれるSwiftコンパイラも必要です。Swiftは文字起こしモデルではなく、この録音プログラムの準備に使います。現在の標準セットアップはコンパイラの有無を確認します。Windows、Linux、Intel Macは動作確認の対象外です。

録音と文字起こしはMac上で行い、APIキーは不要です。日本語訳・要点・概念説明には、Ollama経由のローカルLLM、またはOpenAI APIを使えます。以下で案内する推奨のクラウド構成には、**OpenAIのAPIキーと従量課金のAPI利用枠**が必要です。この構成では音声をMac内に保存し、認識したテキストをクラウドへ送ります。[費用の目安](#講義の長さと費用の目安)と[データの取り扱い](docs/data-handling.md)を確認してください。

リポジトリを取得し、そのディレクトリで初回のセットアップを実行します。依存パッケージと音声認識モデルをダウンロードするため、インターネット接続が必要です。

```sh
./setup.command
```

## 現場で使う前に試す

現場で使う前に、録音済みの音声を使って手元のMacで文字起こし・日本語訳・要点の表示を試せます。

まずは[自分の音声で試す手順](docs/audio-experiments.md)に沿って、英語の録音の先頭2分で試してください。MP3・M4A・WAV・音声付き動画を使えます。文字起こしだけを試すか、有料APIで日本語訳と要点も生成するかを選び、結果を音声と一緒に画面で確認できます。マイクは不要です。

Code for Japanが公開した[Audrey Tangの講演](https://www.youtube.com/watch?v=4_tge6XJhGA)を使った[出力サンプル](samples/audrey-plurality-seoul-2023/README.md)で、英語の文字起こし、日本語訳、要点・概念説明と、実際にかかったAPI費用を確認できます。サンプルを読むだけなら、セットアップやAPI利用は不要です。元動画のライセンス表示はCC BYです。生成結果は未校正です。

音声は同梱されていません。同じ講演音声で試すには、[音声の取得・変換手順](docs/audio-experiments.md#単独講演の入力例)を参照してください。

## マイクで講義を録音して使う

セットアップを済ませ、Macで利用できるマイクを用意してください。以下はマイク録音とクラウド翻訳を使う手順です。録音済みの音声には、上の「現場で使う前に試す」の手順を使います。

まず、送信を許可する範囲と支出上限を設定します。

```sh
cp config/authorization.example.json config/authorization.json
```

コピーしたファイルで、利用する日付、1日あたりの上限金額（米ドル）、文字起こしをクラウドへ送信できる録音時間の上限（最大6時間）を設定します。同梱の例では送信許可が無効、予算がゼロなので、そのままではクラウド処理を開始できません。設定を確認したうえで `human_approved` を `true` にしてください。日付やAPIキーの設定方法は[クラウド設定](docs/cloud-configuration.md)を参照してください。

APIキーを環境変数 `OPENAI_API_KEY` に設定した状態で、次を実行します。キーをファイルに保存する場合は、同ガイドの `--key-file` を使ってください。

```sh
./start.command --check --cloud --authorization config/authorization.json
./start.command --cloud --authorization config/authorization.json
```

1行目は起動準備の確認、2行目は画面を開くコマンドです。画面が開いたら音声入力を選び、録音開始ボタンを押してください。macOSから求められたら、マイクへのアクセスを許可します。

`--cloud` を省くと、Ollama経由のローカルLLMで翻訳・要点・概念説明まで生成できます。Ollamaと使用するモデルは別途導入・起動してください。ローカル処理にはAPIキーは不要で、音声と認識テキストをMac内で処理します。ただし、既定の **`qwen3:4b` では訳や話の関係の取り違えが確認され、講演の理解支援に必要な品質に達していません**。これは評価したモデル・設定についての結果で、すべてのローカルLLMに対する評価ではありません。現在は上記のクラウド構成を推奨します。

ローカルモードは直近範囲の翻訳と理解支援を生成します。未翻訳の原文を順に処理して蓄積する独立した継続翻訳の仕組みは、現在はクラウド構成で利用できます。

録音中はMacの電源を維持し、スリープさせないでください。

## 録音の終了・休憩・次の講演

**「録音を停止」は、API処理を止めるボタンではありません。** 新しい録音を止め、保存済みの音声認識・未翻訳部分・最終分析を処理するため、停止後もAPI費用が発生します。各段階の完了を確認してください。接続待ちは自動で打ち切られず、後で通信が戻ると未処理テキストを送信する場合があります。日次予算の送信前確認はありますが、処理を終える期限とは別です。

ブラウザやタブを閉じても録音・処理は止まりません。残りの処理を保留してアプリの終了を要求する場合は、起動したターミナルで`Ctrl-C`を押します。開始済みのクラウド処理は終了要求後にもAPIを送信・完了し、費用が発生する場合があります。送信済みの要求を取り消す機能もありません。終了確認に失敗した場合は成功扱いにせず、保存された状態を確認してください。保留した処理の自動再開は未実装です。

- **講演途中の休憩：** 同じセッションの録音を一時停止・再開する機能はありません。「閲覧を固定」は表示だけ、「自動再試行を保留」は対象の再試行だけを止めます。現状、休憩を録音に含めない場合は録音を停止し、残処理の終了後に別セッションとして開始します。前半の文脈は自動で引き継がれません。
- **次の講演：** 前の録音・処理が終了した後、同じ画面の「録音を開始」を押します。新しい保存先と空の文脈で始まり、前の記録は残ります。前の失敗・未処理分は自動再開されず、日次予算と送信許可の累計枠はリセットされません。

詳しい停止状態と制約は[操作ガイド](docs/operation.md#finish-before-closing)を参照してください。

## 講義の長さと費用の目安

ローカルでの録音とMLX Whisperによる音声認識には、API料金はかかりません。クラウドでの翻訳・分析には料金がかかります。[過去のライブ運用の観測](docs/experiments/development-handoff.md#partial-live-cost-observation)では、30分間の翻訳・分析を合わせた使用量確認済みのAPI費用は約0.63米ドルで、1時間あたりに換算すると約1.26米ドルでした。当時の`gpt-6.1-sol`設定を使用し、翻訳は通常60秒間隔、分析は通常120秒間隔で実行する構成です。

以下は、同じ費用ペースが続いた場合の概算です。計算には丸め前の観測値を使っています。

| 講義音声の長さ | クラウド翻訳・分析の推定費用（米ドル） |
| --- | ---: |
| 10分 | 0.21 |
| 30分 | 0.63 |
| 1時間 | 1.26 |
| 90分 | 1.89 |
| 6時間 | 7.57 |

この表は過去の観測からの推定で、各時間の実測値や現在の料金表ではありません。費用はモデル、発話量、文脈、出力の長さ、生成間隔、再試行によって変わります。開始・終了時の処理、失敗や費用未確定のリクエスト、同じ予算を使う別の作業に備える追加の余裕は含みません。

[クラウド設定](docs/cloud-configuration.md)で支出上限を設定できますが、予算内での処理完了を保証するものではありません。開発用AIの利用費とMacの電力消費は未測定です。

## 検証結果と限界

本アプリケーションは実験段階です。

- 音声認識や翻訳は、特に固有名詞や未完の文で誤ることがあります。生成した要点や説明にも誤りが含まれる可能性があります。
- 意味のある不確かな認識結果は、不確かさとその理由を付けて翻訳・分析の対象にします。訳が表示されても、元の聞き取りが正確とは限りません。一部の言いよどみや重複は翻訳から省かれますが、原文と除外理由は保存されます。
- 旧版では[Macの実マイクで5時間16分36.864秒の実地利用](docs/experiments/development-handoff.md#long-microphone-field-use)を行いました。保存音声の末尾まで音声認識が完了した一方、録音は入力途絶で終了し、翻訳・分析はHTTP 429で失敗、対象のうち131行が未訳で残りました。長時間の利用実績と、未解決の障害がある状態です。
- 別途、[6時間相当の合成音声を加速して保存する試験](docs/experiments/README.md#accelerated-capture-storage)では、全1,441分割の整合性を確認しました。これは実時間で6時間のマイク運用試験ではありません。Macのバッテリー持続時間、悪い音響条件での精度、障害からの復旧性能、聴講中の理解への効果は未測定です。
- アプリケーション終了後に未完了の処理を自動再開する機能は未実装です。

詳しい測定条件と結果は[実験記録](docs/experiments/README.md)で確認できます。保存済みの文字起こしを使った翻訳試験では、新たなマイク録音、音声認識の精度、発話から画面表示までの遅延は評価できません。v0.9.0の機能と検証範囲は[リリースノート](docs/release-0.9.md)を参照してください。

## リポジトリの構成

| 場所 | 内容 |
| --- | --- |
| `audio-array/` | 録音、ローカル音声認識、キュー、プロバイダ、ダッシュボード、テスト |
| `docs/` | アーキテクチャ、運用、データの取り扱い、リリースの範囲 |
| `docs/experiments/` | 元の発話内容を含まない、公開用の測定概要 |
| `samples/` | 公開講演の文字起こし・翻訳・要点のサンプル |
| `wiki/` | 再利用可能な設計判断と、未解決の開発課題 |
| `CHANGELOG.md` | リリース単位の変更履歴 |

録音・文字起こし・翻訳などのセッションデータは、Git管理外の `data/` と `results/` に保存し、コミットには含めないでください。`samples/` にあるAudrey Tangの公開講演テキストは例外です。音声や生の実行記録は公開対象ではありません。詳しくは[データの取り扱い](docs/data-handling.md)を参照してください。

## 開発時の確認

処理の仕組みを知りたい場合は[アーキテクチャ](docs/architecture.md)、設計の理由や改善案を調べたい場合は[開発Wiki](wiki/index.md)を参照してください。

Python環境を有効にした状態で、テストスイートと2つのJavaScriptチェックを実行します。

```sh
python -m unittest discover -s audio-array/tests -v
node audio-array/tests/test_lecture_ui.js
node audio-array/tests/test_lecture_demo_ui.js
```

通常のテストは合成データを使い、実際のマイク録音、モデル推論、有料APIリクエストは行いません。Swiftの合成音声テストは明示的に有効にした場合のみ実行します。
