# live-lecture-translation

[English](README.md) | [日本語](README.ja.md)

**このプロジェクトの目的は、外国語の講義をリアルタイムで理解する力をAIで拡張することです。** 英語を母語としない人にとって、英語の講義についていくには、母語で聴くときよりも追加の認知的リソースが必要です。AIがその言語的な負担を引き受け、講師が伝えようとしている内容の理解に、より多くの注意を向けられるようにしたいと考えています。

講義を聴きながら使うことを前提に、短時間で内容をつかめること、根拠を手軽に確かめられること、前に表示されていた要点へすぐ戻れることを設計で重視します。聴き手がより少ない負担で講義についていけるかどうかを、成功の基準にします。

Macのマイクから英語の講義を取り込み、リアルタイムで日本語訳とノートを作成するアプリケーションです。録音と音声認識はローカルで実行します。任意でクラウドのテキスト処理を有効にすると、認識した発話に紐づく継続的な日本語訳、要点、解説を生成します。

**バージョン0.9は、既存のアプリケーションを独立したプロジェクトとして切り出したものです。** 継続翻訳の設計を維持しつつ、インストール、設定、開発を元のプロジェクトから分離しています。過去の実験の概要は収録していますが、実験で使用・生成した録音、文字起こし、翻訳、APIレスポンス、スクリーンショットは配布していません。

このリポジトリは、Mac向け講義アプリケーションの正式な開発拠点です。今後のコード変更、実験、現場でのフィードバック、再利用可能な知見はここに蓄積します。まずは[開発Wiki](wiki/index.md)を参照してください。元のデバイス固有のプロジェクトは引き続き別に管理します。開発拠点の移行によって、すでに録音中のセッションを切り替えることはありません。

## 主な機能

- Macの音声入力を選択し、16 kHz・モノラルのPCMと分割WAVファイルとして録音します。
- MLX Whisperを使ってローカルで音声認識します。基準モデルは`large-v3-turbo`で、アプリケーションはローカルのモデルマニフェストを読み込みます。
- 翻訳対象となる未翻訳の発話を順番にキューへ追加し、通常は60秒間隔で翻訳の実行対象にします。成功した翻訳は蓄積され、次の更新でも消えません。
- 話題、話の流れ、要点、概念を、翻訳とは別に通常120秒間隔で更新の実行対象にします。
- 生成した内容を元の発話に紐づけます。不確かな認識結果は画面に残し、翻訳の入力からは除外します。
- 録音、音声認識、クラウド生成を独立して動かします。テキスト処理のリクエストが遅延・失敗しても、それを理由に録音を止めない設計です。
- 最新の処理状況を表示しながら、閲覧位置を固定したり、以前の結果を確認したりできます。

ダッシュボードは現在、日本語で表示されます。主な用途は英語の発話を日本語に翻訳することですが、音声認識では言語の自動判定と日本語も選べます。日本語の原文行は、日本語への翻訳キューには追加しません。

## はじめに

必要な環境は、Apple Silicon搭載のMac、macOSから利用できるマイク、Python 3.12以降、およびAppleのコマンドライン開発ツールに含まれるSwiftコンパイラです。ローカルの音声認識にはMLX Whisperを使用します。このリリースでは、Windows、Linux、Intel Macのサポートを表明していません。

リポジトリのディレクトリで、次のコマンドを実行します。

```sh
./setup.command
cp config/authorization.example.json config/authorization.json
```

セットアップはローカルの実行環境を準備し、指定バージョンに固定された音声認識モデルをダウンロードします。クラウド処理を有効にする前に、コピーした許可設定ファイルを確認・編集してください。同梱のサンプルでは承認が無効で、予算はゼロです。利用を許可する日付、1日あたりの上限金額（米ドル）、処理を許可するテキストの対象時間（最大6時間）を設定し、内容を確認してから承認をtrueにします。APIキーは`OPENAI_API_KEY`または明示的な`--key-file`オプションで指定します。詳しくは[クラウド設定](docs/cloud-configuration.md)を参照してください。

```sh
./start.command --check --cloud --authorization config/authorization.json
./start.command --cloud --authorization config/authorization.json
```

チェックコマンドは録音を開始しません。アプリケーションはポート8776でローカルのダッシュボードを開きますが、開くだけでは録音は始まりません。macOSから求められたらマイクへのアクセスを許可し、入力を選択して準備状況を確認してから、録音開始ボタンを押してください。

通常のマイク入力による利用では、音声はMac内に保存されます。認識したテキストと、そこから選んだ文脈情報は、クラウドでの翻訳・分析のために送信されます。処理の開始から終了までの流れは[運用手順](docs/operation.md)を、生成ファイルを共有する前には[データの取り扱い](docs/data-handling.md)を確認してください。

`--cloud`を付けずに`./start.command`を実行すると、ローカル処理を選択します。継続的なクラウド翻訳は有効になりません。残してあるローカル分析処理は`qwen3:4b`を使用しますが、過去の評価では意味の保持が十分と認められなかったため、クラウドを使う手順と同等のものとしては案内していません。

録音を終えるときは、ダッシュボードの停止ボタンを押し、保存、残りの音声認識・翻訳、最終分析が完了するまで待ってください。録音中はMacの電源を維持し、スリープさせないでください。ターミナルを閉じることは、録音セッションの完了を意味しません。

## 講義の長さと費用の目安

ローカルでの録音とMLX Whisperによる音声認識には、API料金はかかりません。クラウドでの翻訳・分析には料金がかかります。[過去のライブ運用の観測](docs/experiments/development-handoff.md#partial-live-cost-observation)では、直近30分間の翻訳・分析を合わせた使用量確認済みのAPI費用は0.630875米ドルで、1時間あたりに換算すると1.26175米ドルでした。当時の`gpt-6.1-sol`設定を使用し、翻訳は通常60秒間隔、分析は通常120秒間隔で実行する構成です。

同じ費用ペースが続くと仮定した目安は次のとおりです。計算式は`推定米ドル = 1.26175 × 音声の分数 / 60`で、小数点以下2桁に丸めています。

| 講義音声の長さ | クラウド翻訳・分析の推定費用（米ドル） |
| --- | ---: |
| 10分 | 0.21 |
| 30分 | 0.63 |
| 1時間 | 1.26 |
| 90分 | 1.89 |
| 6時間 | 7.57 |

各行は、過去のセッションの途中経過から延長して計算した推定です。それぞれの長さで実測した費用や、現在の料金表ではありません。音声の長さだけで費用は決まらず、モデルの料金、発話の密度、文脈量、出力の長さ、実行間隔、再試行によって変わります。この表には、開始時・終了時の処理、失敗したリクエスト、使用量未確定の予約額、同じ日次予算を使う別の作業への追加の余裕は含めていません。開発用AIの利用費とMacの電力消費も未測定です。[クラウド設定](docs/cloud-configuration.md)で支出上限を設定してください。この推定は、設定した予算内で処理が完了することを保証するものではありません。

## 処理の流れ

```text
Macのマイク
  -> Swiftネイティブ録音 -> ローカルPCM/WAV + フレーム台帳
  -> ローカルMLX Whisper -> タイムスタンプ付きの元の発話
  -> 翻訳キュー          -> 蓄積される日本語訳
  -> 分析スケジューラ    -> 話題、話の流れ、要点、概念
                              |
                        ローカルWebダッシュボード
```

録音は音声認識・生成から独立しています。翻訳と分析は、同時に1件だけ使えるクラウドリクエスト枠を共有します。60秒・120秒という間隔は処理を実行できるタイミングの目安であり、その間隔で必ず新しい結果が表示されるという保証ではありません。音声チャンクの完了待ち、処理待ちのキュー、通信、生成にも時間がかかります。

設計の背景は、[アーキテクチャ](docs/architecture.md)と[開発Wiki](wiki/index.md)を参照してください。

## 検証結果と限界

[実験記録](docs/experiments/README.md)には、過去の開発時の測定をもとに新たに書き起こした概要と、元の発話内容を含まないJSON/CSVの集計データを収録しています。たとえば、330秒の継続翻訳試験では、翻訳対象の原文60行すべてを12ブロックで処理し、対象行の重複・欠落はありませんでした。6回の翻訳リクエストの所要時間の中央値は10.162秒でした。**この試験は保存済みの音声認識結果を再利用したものです。** 新たなマイク録音、音声認識の精度、発話から画面表示までの遅延は測定していません。

バージョン0.9は実験的なリリースです。

- 公開している短時間の試験や加速試験では、長時間のリアルタイムマイク運用、バッテリー持続時間、悪い音響条件での動作、ネットワーク障害からの復旧は確認できていません。
- 音声認識や翻訳は、特に固有名詞や未完の文で誤ることがあります。出力構造の検査や原文への参照があっても、意味の正確さを証明するものではありません。
- アプリケーション終了後に未完了の処理を自動再開する機能は未実装です。
- 認識結果が不確かな場合、その原文行は翻訳から除外されることがあります。キューの処理網羅率が示すのは、翻訳対象となった認識済みの行を処理できた割合であり、発話されたすべての単語を訳せた割合ではありません。
- ローカル分析のコードは残していますが、過去に構造化出力が成功したことだけでは、意味を十分に保持できるとは確認できませんでした。基準となる翻訳手順では、クラウドのテキスト処理を使用します。
- クラウド費用は、文字起こしの密度、文脈量、出力の長さ、モデル、再試行回数によって変わります。公開している費用の外挿値は過去の条件による推定であり、現在の料金や支出を保証するものではありません。

詳しくは[既知の制約と0.9の範囲](docs/release-0.9.md)を参照してください。

その後の[v0.9利用フィードバックと改善課題](wiki/migration-follow-ups.md#field-feedback-proper-name-recognition)には、固有名詞、ユーザー自身の音声による実験、費用の見通し、参照本文や以前の要点へのアクセスを記録しています。これらは今後の改善課題であり、v0.9.0のベースラインに含まれる修正ではありません。

## 開発時の確認

Python環境を有効にした状態で、テストスイートと2つのJavaScriptチェックを実行します。

```sh
python -m unittest discover -s audio-array/tests -v
node audio-array/tests/test_lecture_ui.js
node audio-array/tests/test_lecture_demo_ui.js
```

切り出した0.9のソースでは、Pythonテスト315件が成功し、Swiftによる合成音声テスト2件がスキップされ、失敗はありませんでした。Nodeのチェックも両方成功しました。この検証では、録音、音声認識の推論、APIリクエストの送信、クリーンインストールの確認は行っていません。正確な検証範囲は[リリース検証](docs/release-0.9.md#extraction-validation)を参照してください。
